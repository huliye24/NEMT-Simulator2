# NEMT 项目章程

**版本**: 1.0.0
**创建日期**: 2026-05-02
**状态**: 活跃

---

## 核心原则

### I. 策略优先于代码

每个功能开发必须先有策略规范，再有实施计划，最后才是代码实现。无规范不编码。

### II. 双缓冲验证

所有策略必须经过历史回测 + 实时执行的双重验证才能投入生产。不存在"跳过回测直接实战"的例外。

### III. 可衡量的成功

策略的优劣由数据决定，不是由直觉决定。每个策略必须有明确的核心指标：胜率、夏普比率、最大回撤。

### IV. 风险第一

交易策略的核心是风险管理。任何策略都必须有明确的止损机制和仓位控制。

### V. 熵减驱动

系统设计追求信息熵的持续降低。NEMT 状态机的相位转换是策略决策的核心依据。

## 策略开发工作流

### 阶段 0: 发现 (Discovery)

使用 `/discover` 命令发现新的策略方向。通过数据分析、市场研究、用户反馈识别策略机会。

### 阶段 1: 规范 (Strategy Spec)

使用 `/write-strategy` 命令创建策略规范文档。明确策略假设、目标市场、核心指标。

### 阶段 2: 计划 (Plan)

使用 `/plan-strategy` 命令创建技术实施计划。定义策略参数、回测配置、风险阈值。

### 阶段 3: 回测 (Backtest)

使用 `/backtest` 命令在双缓冲系统中运行历史回测。验证策略在历史数据上的有效性。

### 阶段 4: 实战 (Live Trade)

使用 `/live-trade` 命令在双缓冲系统中运行实时交易。验证策略在当前市场的有效性。

### 阶段 5: 监控 (Monitor)

使用 `/monitor` 命令持续监控策略表现。对比回测与实战的偏差。

## 策略评估标准

### 通过标准 (P0)

| 指标 | 要求 | 原因 |
|------|------|------|
| 胜率 | >= 50% | 高于随机概率 |
| 夏普比率 | >= 1.5 | 风险调整后收益 |
| 最大回撤 | <= 20% | 保护本金 |
| 盈亏比 | >= 1.2 | 覆盖交易成本 |

### 观察标准 (P1)

| 指标 | 要求 |
|------|------|
| 交易频率 | 每周至少 1 笔 |
| 年化收益 | >= 15% |
| 索提诺比率 | >= 2.0 |

### 拒绝标准 (P2)

| 指标 | 阈值 |
|------|------|
| 最大回撤 | > 30% |
| 夏普比率 | < 1.0 |
| 胜率 | < 40% |

## 风险治理

### 仓位管理

- 单笔交易仓位 <= 总资金的 10%
- 同时持仓 <= 5 个策略
- 日亏损上限: 2%
- 周亏损上限: 5%
- 月亏损上限: 10%

### 止损机制

- 硬止损: 价格触及止损位立即平仓
- 软止损: 亏损超过 2% 预警，超过 5% 强制降仓

### 应急机制

- 市场异常波动: 自动暂停所有策略
- 连续亏损 3 天: 自动进入观察模式
- 策略失效率 > 60%: 自动归档策略

## 技术约束

### 策略存储

- 所有策略存于 `web/src/stores/strategyStore.ts`
- 策略参数存于 `web/src/stores/backtestStore.ts`
- 回测结果存于 `web/src/stores/dualBufferStore.ts`

### 依赖

- 市场数据: Binance API
- 前端框架: React + Zustand
- 图表: Canvas 2D (轻量)
- 样式: Tailwind + 内联 CSS
