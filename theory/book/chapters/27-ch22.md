## 审计摘要

对 WCAE-MTS-ADV-0001 五个产出文件进行了系统性理论审计。审计方法：逐条对照新产出（MAIN-001、FORM-001、BRANCH-NETWORK-001、XMAP-001、VALIDATE-001）与其引用的源论文（总论、研究纲领、概念词典、Macro Trend Engine、Market Regime Classifier、NEMT 策略路径、R-001、R-005），检查公式推导链是否完整、概念定义是否一致、映射是否可追溯、结论是否有论文支撑。

## 第一部分：FORM-001 公式推导链审计

### 审计项 1.1：NEMT 顶层公式

**FORM-001 声称：**
```text
NEMT(t) = RiskController(PositionScheduler(
  MacroTrendEngine(MacroData_t),
  MarketRegimeClassifier(MarketData_t, MacroTrendScore_t),
  PortfolioState_t), RiskLimits)
```

**源论文追溯：**

- NEMT 策略路径论文第 4 节定义了八层策略路径：Macro Judgment → Macro Trend Engine → Market Regime Classifier → Asset Allocation Engine → Position State Engine → Risk Control Engine → Rebalance/Execution Engine → Review & Evolution Engine
- NEMT 策略路径论文第 20 节定义了软件架构 `engines/` 目录结构
- Macro Trend Engine 论文第 17 节定义了与 NEMT 的集成：Data Collector → Macro Trend Engine → Market Regime Classifier → Position State Engine → Asset Allocation Engine → Risk Control Engine → Execution/Rebalance Engine → Review & Evolution Engine

**审计发现：**

FORM-001 将八层压缩为四层嵌套函数。压缩逻辑为：(1) Asset Allocation Engine + Position State Engine → PositionScheduler；(2) Review & Evolution Engine 未显式出现在顶层公式中。

**判定：✓ 通过，但有警告。**

顶层公式的压缩是合理的——PositionScheduler 确实合并了资产配置和仓位状态的功能。但 Review & Evolution Engine 作为反馈回路应该被显式表达。建议在顶层公式中增加反馈维度：

```text
NEMT(t+1) = NEMT(t) + η × ReviewEngine(DecisionLog_t, MarketOutcome_t)
```

这表达了 NEMT 是一个自我进化的系统，而不仅仅是静态函数。

### 审计项 1.2：MarketState 七维度

**FORM-001 声称：**
```text
MarketState = {MacroTrend, Regime, Liquidity, RiskAppetite,
               Volatility, Momentum, DrawdownRisk}
```

**源论文追溯：**

```text
| 维度 | 在总论/研究纲领中的出处 | 在概念词典中的出处 |
| MacroTrend | 总论第 8 节"趋势识别必须系统化"→"趋势评分模型" | —（概念词典无"宏观趋势评分"独立条目） |
| Regime | 总论第 4 节"市场阶段比价格点位更重要" | 概念词典"市场阶段层"六阶段 |
| Liquidity | 研究纲领第 2 章"宏观经济基础"→"流动性周期" | 概念词典"流动性周期" |
| RiskAppetite | 研究纲领第 2 章"宏观经济基础"→"风险偏好周期" | 概念词典"风险偏好" |
| Volatility | —（在总论和研究纲领中未作为独立维度） | —（概念词典无独立条目） |
| Momentum | —（同上） | —（概念词典无独立条目） |
| DrawdownRisk | 总论第 9 节"风险控制"→"最大回撤" | 概念词典"最大回撤" |
```

**审计发现：⚠️ 中度问题。**

Volatility 和 Momentum 在概念词典中没有独立的定义条目。它们是金融工程的标准概念，但按照文川院"每个概念必须定义"的纪律，它们应该在概念词典中拥有正式条目。

此外，概念词典"趋势强度"条目中提到了"衡量当前趋势方向性和持续性的量化指标"，这与 Momentum 有概念重叠风险。需要明确区分：Momentum 是价格变化的方向和幅度（描述性），趋势强度是趋势的可靠性和持续性（判断性）。

**建议：** 在概念词典中新增 Volatility（波动率）和 Momentum（动量）两个条目，明确它们与"趋势强度"的区别。

### 审计项 1.3：MacroTrendScore 公式

**FORM-001 声称：**
```text
MacroTrendScore = α₁×LiquidityScore + α₂×RateExpectationScore
  + α₃×DollarPressureScore + α₄×RiskAppetiteScore
  + α₅×FundFlowScore + α₆×OnchainSupplyScore
  - α₇×LeverageRiskScore - α₈×NarrativeOverheatScore
Σαᵢ = 1.0
```

**源论文追溯：**

Macro Trend Engine 论文第 10 节"核心评分公式"：
```text
Macro Trend Score = 宏观友好度 + 流动性评分 + 风险偏好评分
  + 价格趋势评分 + 资金流评分 + 链上供需评分
  - 杠杆拥挤评分 - 情绪过热评分 - 宏观逆风评分
```

**审计发现：⚠️ 需要修正。**

两版公式存在三处差异：

1. **"宏观友好度"的拆分**：MTE 论文用一个"宏观友好度"覆盖了美元、利率、通胀等宏观变量。FORM-001 将其拆为 LiquidityScore + RateExpectationScore + DollarPressureScore 三个子项。这个拆分本身合理（更精细），但 FORM-001 没有说明这个拆分是"对 MTE 论文宏观友好度的细化"，导致读者对比两篇文档时产生不一致的印象。

2. **"价格趋势评分"的消失**：MTE 论文明确包含"价格趋势评分"作为加分项，但 FORM-001 的 MacroTrendScore 中没有对应项。价格趋势信息被放到了 MarketRegimeClassifier 的输入中。这是一个结构性问题——MacroTrendEngine 是否应该包含价格趋势评分？

3. **"宏观逆风评分"的消失**：MTE 论文有"宏观逆风评分"作为扣分项，但 FORM-001 的扣分项只有 LeverageRiskScore 和 NarrativeOverheatScore。如果 DollarPressureScore 和 RateExpectationScore 已经是综合评分（包含了逆风情况），那应该说明这一点。

**建议修正：** 要么在 MacroTrendScore 中补回"价格趋势评分"和"宏观逆风评分"两项，要么在 FORM-001 中明确说明"价格趋势信息已转移至 MarketRegimeClassifier 输入中"以及"宏观逆风已通过 DollarPressureScore 和 RateExpectationScore 的低分区域表达"。

### 审计项 1.5：Position 调度公式与权重矩阵

**FORM-001 声称的权重矩阵：**

```text
| Regime | BTC | ETH | STABLE | CASH | HIGH_BETA |
| STRONG_UPTREND | 0.55 | 0.25 | 0.12 | 0.05 | 0.03 |
```

**源论文追溯：**

NEMT 策略路径论文第 8 节的权重表：

```text
| 市场状态 | BTC | ETH | 稳定币/现金 | 高弹性资产 |
| 强上行趋势 | 45%–65% | 20%–35% | 5%–25% | 0%–10% |
```

**审计发现：⚠️ 轻微不一致。**

NEMT 策略路径论文中 STABLE 和 CASH 是合并的（"稳定币/现金"），而 FORM-001 将它们拆分为两列。拆分本身合理（稳定币和现金有不同的风险特征——稳定币有脱锚风险），但 FORM-001 没有说明拆分原因。

另外，FORM-001 的 STRONG_UPTREND 中 STABLE=0.12 + CASH=0.05 = 0.17，落在策略路径论文的 5%-25% 范围内。ETH=0.25 落在 20%-35% 范围内。BTC=0.55 落在 45%-65% 范围内。数值上是一致的。

**判定：✓ 通过。** 拆分合理，数值在源论文范围内。

### 审计项 4.2：边权重的理论依据

**BRANCH-NETWORK-001 声称：** BacktestEdge 权重 ×2.0，FalsificationEdge 权重 ×2.0。

**审计发现：⚠️ 需要论证增强。**

BRANCH-NETWORK-001 对"回测和反证为什么是最高权重边"的论证是：
1. 回测是将理论与历史数据连接的唯一方式
2. 反证是论文网络的免疫系统

这两个论证是定性的、概念层面的。将"重要性"直接转化为"权重 ×2.0"缺少中间步骤。建议补充一个权重校准框架：

```text
边权重 = 基础权重(1.0) × 可证伪性因子 × 可复现性因子

可证伪性因子：
  - BacktestEdge: 2.0（回测结果可被独立复现）
  - FalsificationEdge: 2.0（反证记录提供了清晰的失效条件）
  - TrendEdge: 1.0（概念定义没有严格的可证伪性）
  - RegimeEdge: 1.0（阶段划分基于共识，难以独立证伪）
  - AllocationEdge: 1.0（仓位逻辑的优劣需要回测验证）
  - SignalEdge: 0.8（信号的 IC 值高度依赖市场阶段）

可复现性因子：
  - BacktestEdge: 1.0（给定相同数据和规则，可复现）
  - FalsificationEdge: 0.8（相同条件不一定每次都触发失效）
```

这样权重就有了方法论依据，而不只是断言。
