## 一、NEMT 系统总公式

### 1.1 顶层公式

```text
NEMT(t) =
  RiskController(
    PositionScheduler(
      MacroTrendEngine(MacroData_t),
      MarketRegimeClassifier(MarketData_t, MacroTrendScore_t),
      PortfolioState_t
    ),
    RiskLimits
  )
```

**变量定义：**

```text
| 符号 | 含义 | 数据类型 | 更新频率 |
| MacroData_t | t 时刻的宏观数据集 | Vector[10] | 日/周 |
| MarketData_t | t 时刻的市场数据集 | Vector[n] | 日 |
| MacroTrendScore_t | 宏观趋势评分 | Scalar [0,100] | 日 |
| MarketRegime_t | 市场阶段标签 | Enum(10) | 日/周 |
| PortfolioState_t | 当前组合状态 | Struct | 实时 |
| RiskLimits | 硬风险约束集合 | Struct | 月/季审查 |
```

### 1.2 信息流向

```text
MacroData_t ──→ MacroTrendEngine ──→ MacroTrendScore_t ──┐
                                                          ├──→ PositionScheduler ──→ TargetPosition ──→ RiskController ──→ ConstrainedPosition
MarketData_t ──→ MarketRegimeClassifier ──→ MarketRegime_t ──┘                    PortfolioState_t                    RiskLimits
```

## 二、市场状态对象 MarketState

### 2.1 完整定义

```text
MarketState_t = {
  MacroTrend:      Enum {STRONG_TAILWIND, WEAK_TAILWIND, NEUTRAL, WEAK_HEADWIND, STRONG_HEADWIND},
  Regime:          Enum {STRONG_UPTREND, WEAK_UPTREND, SIDEWAYS_BULLISH, SIDEWAYS_NEUTRAL,
                         SIDEWAYS_BEARISH, WEAK_DOWNTREND, STRONG_DOWNTREND,
                         LATE_BULL_RISK, BOTTOM_FORMATION, REVERSAL_WATCH},
  Liquidity:       Scalar [0, 100],  // 流动性充裕度评分
  RiskAppetite:    Scalar [0, 100],  // 市场风险偏好评分
  Volatility:      Scalar [0, 100],  // 波动率水平评分（越高越危险）
  Momentum:        Scalar [-100, 100], // 价格动量（正=上行，负=下行）
  DrawdownRisk:    Scalar [0, 100]   // 当前回撤风险评分（越高越危险）
}
```

### 2.2 各维度的计算逻辑

#### 2.2.1 Liquidity（流动性评分）

```text
Liquidity_t =
    w_liq1 × f1(FedBalanceSheet_t)      // 美联储资产负债表变化
  + w_liq2 × f2(GlobalLiquidity_t)      // BIS 全球流动性指标
  + w_liq3 × f3(StablecoinMCap_t)       // 稳定币市值变化率
  + w_liq4 × f4(CreditSpread_t)         // 信用利差（反向）
  + w_liq5 × f5(USDIndex_t)             // 美元指数（反向映射）
```

归一化至 [0, 100]，>70 表示流动性充裕。

#### 2.2.2 RiskAppetite（风险偏好评分）

```text
RiskAppetite_t =
    w_ra1 × f6(VIX_inverse)             // VIX 的反向映射
  + w_ra2 × f7(BTC_Dominance_trend)     // BTC 市值占比变化方向
  + w_ra3 × f8(Altcoin_Volume_Ratio)    // 山寨币交易量占比
  + w_ra4 × f9(ETF_Flow_Direction)      // ETF 资金流向
  + w_ra5 × f10(Funding_Rate)           // 资金费率（过高=过热）
```

#### 2.2.3 Volatility（波动率评分）

```text
Volatility_t =
    Scale_0_100(RealizedVol_30d_t / RealizedVol_90d_t)

// 当前 30 日波动率相对于 90 日波动率的比值
// >1 = 波动率上升（风险增加），<1 = 波动率下降（市场趋于稳定）
```

#### 2.2.4 Momentum（动量评分）

```text
Momentum_t =
    w_m1 × PriceReturn_7d
  + w_m2 × PriceReturn_30d
  + w_m3 × PriceReturn_90d
  + w_m4 × MACD_Signal

// 多时间框架动量叠加
// 正 = 上行趋势，负 = 下行趋势
```

#### 2.2.5 DrawdownRisk（回撤风险评分）

```text
DrawdownRisk_t =
    w_dr1 × Distance_to_ATH          // 距离历史高点的距离
  + w_dr2 × Leverage_Ratio_t          // 市场杠杆水平
  + w_dr3 × LongLiquidation_Volume    // 多头爆仓量（近期）
  + w_dr4 × Overheat_Indicator        // 综合过热指标
```

## 三、Macro Trend Engine 公式

### 3.1 核心公式

```text
MacroTrendScore_t =
    α₁ × LiquidityScore(MacroData_t)
  + α₂ × RateExpectationScore(MacroData_t)
  + α₃ × DollarPressureScore(MacroData_t)
  + α₄ × RiskAppetiteScore(MacroData_t)
  + α₅ × PriceTrendScore(MacroData_t)
  + α₆ × FundFlowScore(MacroData_t)
  + α₇ × OnchainSupplyScore(MacroData_t)
  - α₈ × LeverageRiskScore(MacroData_t)
  - α₉ × NarrativeOverheatScore(MacroData_t)
  - α₁₀ × MacroHeadwindScore(MacroData_t)
```

**约束：**

```text
Σαᵢ = 1.0  (正向项权重归一化)
MacroTrendScore_t ∈ [0, 100]
```

**与源论文的对应关系：** 此公式是 Macro Trend Engine 论文第 10 节"核心评分公式"的精确化版本。MTE 论文使用"宏观友好度"统摄美元、利率和通胀三个宏观变量；本公式将其拆分为 LiquidityScore、RateExpectationScore 和 DollarPressureScore 三个可独立计算的子项（细化而非改变）。MTE 论文的"价格趋势评分"对应本公式的 PriceTrendScore。MTE 论文的"宏观逆风评分"对应本公式的 MacroHeadwindScore（独立为扣分项，避免被综合在正向项中稀释）。

### 3.2 子评分函数

```text
LiquidityScore(MacroData_t) =
  100 × (CurrentGlobalLiquidity - MinGlobalLiquidity_5y)
      / (MaxGlobalLiquidity_5y - MinGlobalLiquidity_5y)

RateExpectationScore(MacroData_t) =
  100 - 100 × (FedFundsRate_t - MarketImpliedRate_6m) / MaxSpread

DollarPressureScore(MacroData_t) =
  100 - 100 × (DXY_t - DXY_min_1y) / (DXY_max_1y - DXY_min_1y)
  // 美元越弱，评分越高

FundFlowScore(MacroData_t) =
  100 × (BTC_ETF_NetFlow_30d + Stablecoin_MCap_Change_30d)
      / MaxHistoricalFlow

OnchainSupplyScore(MacroData_t) =
  100 × (LongTermHolder_Supply_Ratio + Exchange_Outflow_Ratio) / 2

LeverageRiskScore(MacroData_t) =
  100 × (Current_OpenInterest / Historical_Max_OI)
  × (1 + Funding_Rate_Excess)

NarrativeOverheatScore(MacroData_t) =
  100 × (SocialVolume_t / SocialVolume_90d_avg - 1)
  // 社交媒体讨论度异常升高时触发

PriceTrendScore(MacroData_t) =
  100 × (w_pt1 × Price_above_200MA + w_pt2 × HigherHigh_Structure
       + w_pt3 × Volume_Confirmation + w_pt4 × Support_Respect)
  // 价格趋势结构评分：均线上方、高低点结构、量能确认、支撑有效性
  // 综合评分 0-100，>60 表示技术趋势健康

MacroHeadwindScore(MacroData_t) =
  100 × (w_hw1 × Rate_Hike_Pressure + w_hw2 × Dollar_Strength_Excess
       + w_hw3 × Financial_Conditions_Tightening + w_hw4 × Credit_Stress)
  // 宏观逆风评分：加息压力、美元过强、金融条件收紧、信用压力
  // 独立为扣分项，确保宏观逆风不因其他正向评分而被稀释
```

## 四、Market Regime Classifier 公式

### 4.1 分类逻辑

```text
MarketRegime_t = Classify(MacroTrendScore_t, Momentum_t, Volatility_t, RiskAppetite_t)
```

> **注意：以下所有数值阈值（70、55、40、30 等）均为初始设计值，需要经过回测校准和样本外验证后才能作为实际策略参数使用。**

### 4.2 分类规则矩阵

```text
IF MacroTrendScore > 70 AND Momentum > 30 AND Volatility < 60:
    → STRONG_UPTREND

IF MacroTrendScore IN [55, 70] AND Momentum > 0 AND Volatility < 70:
    → WEAK_UPTREND

IF MacroTrendScore IN [40, 60] AND Momentum IN [-20, 20]:
    → SIDEWAYS_NEUTRAL

IF MacroTrendScore IN [40, 55] AND Momentum > 10:
    → SIDEWAYS_BULLISH

IF MacroTrendScore IN [40, 55] AND Momentum < -10:
    → SIDEWAYS_BEARISH

IF MacroTrendScore < 40 AND Momentum < -30:
    → STRONG_DOWNTREND

IF MacroTrendScore IN [30, 45] AND Momentum < 0:
    → WEAK_DOWNTREND

IF MacroTrendScore > 60 AND Momentum > 40 AND Volatility > 80:
    → LATE_BULL_RISK
    // 高趋势 + 高动量 + 高波动 = 牛市可能进入末期

IF MacroTrendScore < 35 AND Momentum > -10 AND DrawdownRisk > 60:
    → BOTTOM_FORMATION
    // 低趋势 + 动量不再恶化 + 价格低位 = 可能筑底

IF ABS(Momentum_t - Momentum_t-1) > 40 AND Volatility > 75:
    → REVERSAL_WATCH
    // 动量剧烈变化 + 高波动 = 注意反转
```

### 4.3 分类置信度

```text
RegimeConfidence_t = 1 - (BoundaryDistance_t / MaxBoundaryDistance)

其中：
  BoundaryDistance_t = 当前状态向量到最近分类边界的距离
  距离越远 → 置信度越高
  距离越近 → 存在分类不确定性 → 仓位应更保守
```

## 五、Position Scheduler 公式

### 5.1 核心调度公式

```text
Position(t+1) = Adjust(Position(t), MarketState(t), RiskBudget(t))
```

### 5.2 目标权重生成

```text
TargetWeight(i, Regime) = BaseWeight(i, Regime) × RegimeConfidence × RiskBudget_Ratio

其中：
  BaseWeight(i, Regime)：资产 i 在 Regime 下的基准权重（查表）
  RegimeConfidence：当前状态分类的置信度
  RiskBudget_Ratio：当前风险预算占最大风险预算的比例
```

### 5.3 资产基准权重矩阵

```text
                    BTC     ETH     STABLE    CASH     HIGH_BETA
STRONG_UPTREND     0.55    0.25     0.12     0.05      0.03
WEAK_UPTREND       0.50    0.18     0.22     0.07      0.03
SIDEWAYS_BULLISH   0.40    0.12     0.35     0.10      0.03
SIDEWAYS_NEUTRAL   0.30    0.08     0.45     0.15      0.02
SIDEWAYS_BEARISH   0.20    0.05     0.55     0.18      0.02
WEAK_DOWNTREND     0.12    0.03     0.60     0.23      0.02
STRONG_DOWNTREND   0.08    0.00     0.67     0.25      0.00
LATE_BULL_RISK     0.40    0.12     0.35     0.10      0.03
BOTTOM_FORMATION   0.35    0.10     0.40     0.13      0.02
REVERSAL_WATCH     0.20    0.05     0.50     0.20      0.05
```

### 5.4 调整函数

```text
Adjust(Position(t), TargetWeight, MarketState(t)) =

  FOR each asset i:
    delta_i = TargetWeight(i) - CurrentWeight(i)

    IF |delta_i| < RebalanceThreshold:
        // 偏离不大，不调整
        new_weight_i = CurrentWeight(i)

    ELSE IF |delta_i| > MaxSingleAdjust:
        // 超出单次调整上限，分批调整
        new_weight_i = CurrentWeight(i) + sign(delta_i) × MaxSingleAdjust

    ELSE:
        new_weight_i = TargetWeight(i)
```

## 六、Risk Controller 公式

### 6.1 风险控制函数

```text
Position'(t+1) = RiskController(Position(t+1), RiskLimits, MarketState(t))
```

### 6.2 硬约束规则

```text
Rule 1: BTC_Weight ≤ 0.65
Rule 2: ETH_Weight ≤ 0.35
Rule 3: HIGH_BETA_Weight ≤ 0.10
Rule 4: (STABLE_Weight + CASH_Weight) ≥ 0.15  // 最低防守缓冲
Rule 5: IF DrawdownRisk > 70:禁止增加任何风险资产权重
Rule 6: IF Regime == LATE_BULL_RISK: 强制 CASH_Weight ≥ 0.10
Rule 7: IF Regime == STRONG_DOWNTREND: 禁止 ETH_Weight > 0 且禁止 HIGH_BETA_Weight > 0
Rule 8: |new_weight_i - current_weight_i| ≤ 0.08  // 单次最大调整
Rule 9: TurnoverRate_30d ≤ 1.0  // 30 日换手率上限
```

### 6.3 风险预算公式

```text
RiskBudget(t) = MaxRiskBudget × RiskBudgetMultiplier(MarketState(t))
```

> **理论来源说明：** RiskBudgetMultiplier 是本公式系统的原创理论扩展。在已有研究论文（总论、MTE、MRC、NEMT 策略路径）中，风险预算的概念隐含在仓位上限和最大回撤的讨论中，但未形式化为一个独立的状态依赖乘数。本公式将其显式化——市场状态越好，允许使用的风险预算比例越高。这一概念需要在回测中独立验证其有效性。

RiskBudgetMultiplier(Regime) =
  STRONG_UPTREND:     1.0
  WEAK_UPTREND:       0.80
  SIDEWAYS_BULLISH:   0.60
  SIDEWAYS_NEUTRAL:   0.40
  SIDEWAYS_BEARISH:   0.25
  WEAK_DOWNTREND:     0.15
  STRONG_DOWNTREND:   0.05
  LATE_BULL_RISK:     0.50  // 仍可参与但需格外谨慎
  BOTTOM_FORMATION:   0.30  // 试探性布局
  REVERSAL_WATCH:     0.20  // 等待确认
```

## 七、反馈更新公式

### 7.1 绩效评估

```text
PerformanceScore(period) =
    w_p1 × Return_vs_Benchmark
  + w_p2 × Sharpe_Ratio
  + w_p3 × Max_Drawdown_Score    // 回撤越小，分数越高
  + w_p4 × Regime_Accuracy       // 状态分类准确率
  + w_p5 × Execution_Quality     // 调仓执行质量

其中：
  Regime_Accuracy = (正确分类的天数) / (总天数)
  Execution_Quality = 1 - (实际滑点 / 最大允许滑点)
```

### 7.2 模型参数更新

```text
α_i(t+1) = α_i(t) + η × ∂PerformanceScore / ∂α_i

// 权重参数通过绩效反馈逐步优化
// η 是学习率，应设置得很小以防止过度拟合
```

### 7.3 触发反证检查的条件

```text
IF MaxDrawdown > AllowedMaxDrawdown:
    触发反证检查 → 检查仓位调度逻辑是否在某种 Regime 中系统性失效

IF Regime_Accuracy < 0.5:
    触发反证检查 → 检查 MarketRegimeClassifier 的分类规则是否需要修正

IF PerformanceScore < 0 AND Regime == STRONG_UPTREND:
    触发反证检查 → 强趋势中亏损，说明趋势方向判断或仓位逻辑有严重问题
```
