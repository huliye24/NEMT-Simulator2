# DeepSeek 执行指令：收敛 NEMT Studio 策略闭环

> 日期：2026-10-22  
> 任务性质：先恢复真实性与一致性，再做视觉优化。禁止继续扩页面、换概念或制造“看起来已完成”的假闭环。

## 可直接发送给 DeepSeek 的指令

你现在是 NEMT Simulator 的执行工程师。你的目标不是继续设计新页面，而是把当前分裂、半接通的实现收敛成一个可验证的最小闭环。

### 0. 强制前置检查

1. 先读根目录 `AGENTS.md` 和当前目录链上的全部 `AGENTS.md`。
2. 查找并读取 `.cursor/rules/DIRECTION_LOCK.md`、`CORE_MODEL.md`、`docs/ENTRY.md`、`docs/ARCHITECTURE.md`、`docs/RULES.md`、`docs/STATE.md`。
3. 如果这些文件不存在，明确记录“文档与仓库现实不一致”，不得猜测其内容。本仓库当前已确认上述文件缺失，只有根 `AGENTS.md` 提供方向锁摘要。
4. 在任何修改前输出：
   - 当前真实技术栈；
   - 当前允许修改目录；
   - 本任务所需文件是否都在允许范围；
   - `git status --short` 中与你将修改的文件相关的既有改动。
5. 若完成真实闭环必须修改方向锁之外的文件，立即停止，不得偷偷修改；列出需要解锁的精确文件及原因，等待用户授权。

### 1. 当前事实基线

- `web` 当前是 Next.js 16.3.2 + React 19.2.8，不是根 `AGENTS.md` 所描述的 React 18 + Vite。
- 当前产品同时残留旧 mock 控制台、旧 Trade UI、新 Studio UI 三套路径。不要再创建第四套。
- 本轮最新主线是：`策略仓库 -> Python 回测 -> 部署到模拟盘 -> 执行页查看/控制`。
- `npm run build` 当前通过，但有 Turbopack 动态文件系统追踪警告。
- `npm run lint` 当前失败，共 4 个 error、15 个 warning。与本轮直接相关的 error 位于：
  - `web/src/components/trade/studio/StudioApp.tsx`
  - `web/src/components/trade/studio/pages/ExecutionPage.tsx`
  - `web/src/components/trade/studio/pages/StrategiesPage.tsx`
- 当前“部署到模拟盘”只把一条记录写入浏览器 `localStorage`；执行页真正展示和控制的是后端 `/strategy/board` 与 `/strategy/auto-trade`。二者不是同一个数据源，所以“已部署”只是 UI 文案，不会让刚回测的策略被后端执行。
- 当前回测接口会执行浏览器提交的 Python 源码。CLI token 又可由浏览器端接口取得；这只能作为受控本地开发能力，不能被描述为生产级安全执行沙箱。
- 当前回测使用最近最多 1000 根 Binance 1h/4h K 线，结果不是完整历史验证，也不能据此宣称策略已经可实盘。

### 2. 唯一目标

把现有界面收敛为一个“诚实可用”的最小工作流：

1. 用户在策略页创建或导入一个 Python 策略仓库；
2. 用户选择入口文件并运行回测；
3. UI 清楚展示数据区间、K 线数量、费用、滑点、结果与失败原因；
4. 用户点击“部署到模拟盘”时，系统必须满足以下二选一：
   - A：真正把策略版本与配置提交给后端，并由执行页读取同一部署记录；
   - B：如果后端尚无部署能力，把按钮和文案改为“保存为模拟盘候选”，并明确显示“尚未接入自动执行”，绝不伪装成已部署；
5. 执行页只展示真实后端状态；本地候选记录必须与真实运行策略分区显示，不能混成同一个“运行中”列表；
6. 所有变更通过 lint、build，并提供人工验收步骤。

### 3. 实施顺序

严格按顺序执行，每完成一步再进入下一步：

#### 阶段 A：建立真实数据流图，不改代码

列出下列交互的调用链、数据源和持久化位置：

- 新建/导入策略仓库；
- 保存仓库；
- 运行 Python 回测；
- 保存回测结果；
- 部署到模拟盘；
- 执行页加载策略；
- 启停自动交易。

用表格标记每项是 `真实后端`、`localStorage`、`内存状态` 或 `静态 mock`。明确指出断链位置。

#### 阶段 B：先修“说真话”

在方向锁允许范围内完成：

- 修复本轮相关的 ESLint errors；不要用禁用规则规避。
- 把本地部署记录重命名为“模拟盘候选”或同义准确名称。
- 执行页把“后端真实运行策略”和“本地候选策略”分区。
- 删除会让用户误以为已真实部署、已自动执行、已生产可用的文案。
- 保留现有视觉语言，不重做导航、不新增大图、不再改品牌名。

#### 阶段 C：真实部署设计

如果方向锁允许所需后端和 API 文件：

- 设计单一部署契约，至少包含 `deployment_id`、`repository_id`、`strategy_version/hash`、`entry`、`symbol`、费用、滑点、创建时间、状态与最后错误；
- 部署、执行页、自动交易必须读取同一服务端事实源；
- 不允许以 localStorage 作为真实部署状态；
- 不允许直接在 Web 进程中无隔离执行不可信 Python。若暂时只能本地开发执行，必须维持开发环境开关并显著标注限制；
- 为部署契约和状态转换补最小测试。

如果方向锁不允许，停止在阶段 B，提交“所需解锁清单”，不得绕过限制。

#### 阶段 D：验证

必须实际运行并报告完整结果：

```powershell
cd web
npm run lint
npm run build
```

然后人工验证：

1. 新建策略仓库；
2. 修改并保存 Python 文件；
3. 运行回测并看到真实结果；
4. 刷新页面后仓库仍存在；
5. 点击“保存为模拟盘候选”或真实“部署”，文案与实际能力一致；
6. 执行页能区分候选与后端运行策略；
7. 后端不可用时显示明确错误，不回退成假运行数据；
8. 登录、退出和 localhost 行为一致，不出现闪屏或绕过登录的隐式状态切换。

### 4. 禁止事项

- 禁止新增页面、导航组、品牌概念、海报或装饰性大图。
- 禁止重写整个组件或 CSS 文件来“顺手整理”。
- 禁止把 mock/localStorage 数据称为实时、真实、已部署或运行中。
- 禁止为通过检查而关闭 ESLint/TypeScript 规则。
- 禁止改动方向锁之外的目录。
- 禁止删除用户已有改动、执行 `git reset --hard` 或覆盖整个文件。
- 禁止顺手修复与本任务无关的旧 warning；只记录，不扩大范围。
- 禁止在没有测试证据时宣称“完成”。

### 5. 每次回复格式

每次只报告以下五项，不写泛泛总结：

1. 本次目标；
2. 读取到的事实；
3. 修改文件及每个文件的理由；
4. 验证命令与原始结果；
5. 尚未完成、风险或需要用户决定的事项。

### 6. 完成定义

只有同时满足以下条件才能说“完成”：

- 用户看到的部署/运行状态与真实数据源一致；
- 不再把本地候选伪装成服务端运行策略；
- 本轮相关 lint error 为 0；
- `npm run build` 成功；
- 给出可复现的人工验收记录；
- 未越过方向锁；
- 没有新增另一套并行实现。

现在先执行阶段 A。阶段 A 完成后，如果发现所需改动超出方向锁，只输出解锁清单并停止，不要自行继续。

## 给项目负责人的判断

当前最应该停掉的是“继续做界面”。真正阻塞预期的是事实源不统一：策略页宣布部署成功，执行页却读取另一套后端策略看板。只要这条链没有统一，继续调整布局、按钮或文案都会产生更多错觉和返工。
