# S-005.A.1 — 账户账本、保证金与清算审计

- **微任务范围**：只做资金守恒与清算机制的修复与审计，不研究如何保留极端盈利
- **实现**：`backend/emergenzix_api/nemt_strategy/s005_account.py`
- **测试**：`backend/tests/test_s005_account.py` — **11 项全通过**
- **证据等级**：工程审计（不是策略结论）｜**订单权限**：无

## 0. 这项审计发现的第一个问题：我自己之前的组合模拟是错的

审计过程中重放了 1,049 笔真实交易（10 币 × 2022–2025 连续），
发现**此前报告里的两个组合模拟都不能用**：

| 方法 | 问题 | 方向 |
| --- | --- | --- |
| 按 R 直接复利（naive） | 完全忽略保证金、可用余额与拒绝逻辑，**凭空创造购买力** | **高估** |
| 早期的组合模拟 | 把"未实现盈亏"当成"占用风险"来计算总风险上限，导致过度跳过交易 | 低估 |

**"事件级 R 累加"和"真实账户复利"确实存在巨大差异，这个判断是对的。**

## 1. 五项审计结果

### 检查 1：100 USDT 初始资本，每笔权益变化是否正确？

✅ **通过。** 单笔往返测试：权益变化 **精确等于**净 PnL（`test_single_trade_equity_change_equals_net_pnl`）。
并额外加了等价性回归：**顺序交易（一次一仓）时，账户终值 == Π(1+f·R)，误差 < 0.5%**
（`test_sequential_trades_match_direct_compounding`）。

### 检查 2：持仓 / 可用余额 / 未实现盈亏 / 手续费是否一致？

✅ **通过。** 5 条不变量在**每次标记**时断言，违反即抛 `AccountingError`：

| 不变量 | 内容 |
| --- | --- |
| I1 | `free_cash >= 0` |
| **I2** | `free_cash + 锁定保证金 + 未结仓入场费 == 初始资本 + 已实现净额` |
| I3 | `Σ 锁定保证金 ≤ 初始资本 + 已实现净额` |
| I4 | `realised_net == 所有已平仓净 PnL 之和` |
| I5 | `equity >= 0` |

> **I2 是非平凡不变量**：入场费已从现金扣走但只在平仓时进入已实现净额，
> 所以它必须桥接两边。这条在修复前是恒等式（形同虚设），是我第一版的缺陷。

### 检查 3：会不会因杠杆或保证金不足触发清算？

✅ **机制验证通过，本数据集未触发。**

- 清算判定：`equity ≤ Σ 维持保证金` → 强制平仓
- **强平按"强平价"成交**（用二分法求 `equity == 维持保证金` 的价格），
  而不是按市价成交——这是保证亏损不超过保证金、`free_cash` 不为负的关键
- 测试覆盖：跳空穿仓 → 清算触发、`equity >= 0`、罚金 = 名义 × 1%
- **在 1,049 笔真实交易里 0 次清算**：2N 止损（约 2.5% 距离）在 3 倍杠杆下
  总是先于维持保证金（1%）触发

⚠️ **限制**：重放只在**入场价与出场价**两点标记，没有逐根 K 线。
真实的插针跳空（例如先穿止损再穿强平价）可能触发清算，本审计**没有覆盖**。

### 检查 4：多币种同时出现机会时，是否违反统一账户风险预算？

⚠️ **发现真实约束：并发数量由保证金决定，不由我设定的"仓位上限"决定。**

3 倍杠杆、约 2.5% 止损距离下的**精确**容量：

| 单笔风险 | 每仓名义 | 每仓保证金 | **最多并发仓位数** |
| ---: | ---: | ---: | ---: |
| 1.0% | 0.40× 权益 | 0.133× 权益 | **7** |
| 2.0% | 0.80× 权益 | 0.267× 权益 | **3** |
| 5.0% | 2.00× 权益 | 0.667× 权益 | **1** |
| 7.5% | 3.00× 权益 | 1.000× 权益 | **1** |

**这意味着我此前报告过的某些组合是不可执行的：**

| 此前报告 | 声明的并发 | 实际可执行 | 结论 |
| --- | ---: | ---: | --- |
| `5% 风险 · 2 仓` = 6.28 倍 | 2 | **1** | **不可执行** |
| `7.5% 风险 · 3 仓` | 3 | **1** | **不可执行** |
| `2% 风险 · 3 仓` = 1.68 倍 | 3 | 3 | 恰好可行 |
| `1% 风险 · 3 仓` | 3 | 7 | 可行 |

真实交易中的拒绝统计（L1 只做多，354 笔）：

| 单笔风险 | 实际成交 | 被拒 | 拒绝原因 |
| ---: | ---: | ---: | --- |
| 1.0% | 294 | 60 | 保证金 15 / 风险预算 45 |
| 2.0% | 147 | 207 | 保证金 37 / 风险预算 170 |
| 5.0% | 63 | **291** | 保证金 120 / 风险预算 171 |
| 7.5% | 65 | **289** | 保证金 260 / 风险预算 29 |

**在 5% 风险下，354 笔里只有 63 笔能用真钱开出来。**

### 检查 5：资金不足时是否拒绝新仓，而不是创造虚拟购买力？

✅ **通过。** `can_open()` 在三种情况下返回拒绝且**不产生任何状态变化**：

- `insufficient_margin`：所需保证金 > 可用余额
- `risk_budget`：总在场风险 + 新风险 > 7.5% 权益
- `already_open`：同币已有持仓

测试验证：被拒后 `free_cash` 不变、`fees_paid` 不变、`positions` 为空
（`test_insufficient_margin_rejects_instead_of_virtual_leverage`）。

## 2. 审计暴露的三处方法论错误（这是最有价值的部分）

### 错误一：naive R 复利高估到什么程度

同一批 354 笔（L1，和 695 笔 R0），三种口径：

| 单笔风险 | naive R 复利 | 严格账户 | **naive / 严格** |
| ---: | ---: | ---: | ---: |
| 1.0% | 159,995 | 52,695 | **3.0×** |
| 2.0% | 960,162 | 114,001 | **8.4×** |
| 5.0% | 8,712,077 | 55,978 | **156×** |
| 7.5% | 6,114,308 | 50,309 | **122×** |

**风险越高，naive 口径的虚高越严重**——因为它让每一笔都用"全额可用"，
而真实账户在高风险下只能开 1 仓。

### 错误二：严格账户的权益路径仍不是最终值

重放只在入场/出场两点标记，**未平仓浮盈没有进入定价基准**，
所以并发时每笔的 `risk = f × 权益` 建立在"未实现盈亏≈0"的权益上。
这让严格账户的数字偏低（可视为**下界**）。

**因此真实的账户终值在两者之间，需要逐根 K 线标记才能定稿。**
这是下一项微任务的必要前置，不是本项能解决的。

### 错误三：手续费从未进入任何组合口径

| 单笔风险 | 累计手续费（L1，4 年） |
| ---: | ---: |
| 1.0% | 1,814 USDT |
| 2.0% | 3,475 USDT |

在 1 万 U 本金上，1% 风险档的手续费已占资本的 **18%**。
naive 复利口径完全不含这项。

## 3. 判定

| 审计问题 | 结果 |
| --- | --- |
| 每笔权益变化是否正确 | ✅ 精确 |
| 持仓/可用/浮盈/手续费是否一致 | ✅ 5 条不变量每次标记断言 |
| 是否可能因保证金不足清算 | ✅ 机制正确；本数据集 0 次；**未覆盖逐根插针** |
| 是否违反统一预算 | ✅ 强制生效；**并发现并发受保证金硬约束** |
| 资金不足是否拒绝而非创造虚拟购买力 | ✅ 拒绝且无状态变化 |

**结论：账本层通过审计。但审计同时证明，此前若干组合结论建立在不存在的购买力之上，
必须作废或重算。**

## 4. 必须作废或重算的既有结论

| 结论 | 状态 |
